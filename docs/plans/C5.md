# C5 Illustrative automation value calculator

**Why:** Visitors on `/case-studies` should be able to reason about potential time saved from automation using visible, adjustable assumptions. Output is explicitly labelled as an illustrative scenario, never a measured client result. No ROI / benchmark / guarantee wording.

## Model

No persistence, no backend. One pure function:

```ts
// src/lib/value-calculator.ts
export type SavingsInput = {
  volume: number           // items per month
  minutesPerItem: number   // manual handling time per item
  hourlyCost: number       // loaded cost per hour, unit-less number
  reductionFraction: number // 0..1 share of handling time removed
}
export type SavingsOutput = { hoursSaved: number; laborTimeValue: number }

export const DEFAULT_SAVINGS_INPUT: SavingsInput = {
  volume: 100, minutesPerItem: 10, hourlyCost: 30, reductionFraction: 0.5,
}

export function estimateSavings(i: SavingsInput): SavingsOutput
// hoursSaved = volume * minutesPerItem / 60 * reductionFraction
// laborTimeValue = hoursSaved * hourlyCost
// Non-finite or negative inputs are clamped to 0; reductionFraction clamped to [0, 1].
```

Defaults: 100, 10, 30, 0.5 -> hoursSaved 8.333..., laborTimeValue 250.

## Screens / Routes

`/$lang/case-studies` (existing index). Below the `<ul>` card list, render `<ValueCalculator />` once.

Component layout (single section, `border-t border-line pt-8 mt-8`):
- `<h2>` `t('calculator.title')`
- `<p>` `t('calculator.disclaimer')` in `text-fg-muted`
- Grid of four fields (`sm:grid-cols-2 gap-4`), each `<Label htmlFor>` + `<Input type="number">`:
  - volume: `min=0 step=1`
  - minutesPerItem: `min=0 step=1`
  - hourlyCost: `min=0 step=1`
  - reduction: shown as percent `min=0 max=100 step=5`, stored as fraction (`value / 100`)
- Two outputs (`<dl>`): `t('calculator.outputs.hours')` -> `hoursSaved.toFixed(1)` + ` h`; `t('calculator.outputs.value')` -> `Math.round(laborTimeValue)`
- `<p>` `t('calculator.assumptions')` in `text-[13px] text-fg-muted`

States: no loading, no error. Empty or invalid input -> `Number(value)` is NaN -> helper clamps to 0 -> outputs show `0.0 h` / `0`. State is local `useState<SavingsInput>` initialised from `DEFAULT_SAVINGS_INPUT`. No `useEffect`, no form submit, no analytics.

Formatting: plain `toFixed(1)` / `Math.round`. No `Intl.NumberFormat`, no currency symbol (locale copy says "per hour" in generic units).

## Limits

- Unit-less money: hourly cost and value shown as plain numbers, no currency symbol or conversion.
- Reduction entered as whole percent (0–100, step 5) for usability; helper still takes a 0..1 fraction.
- No persistence, analytics, charts, or per-concept placement (task non-goals).
- Native `<input type="number">` only; no slider, no custom stepper.
- Test runner is bare `node --test`; no vitest/jest added.

## Risks
